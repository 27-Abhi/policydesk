# PolicyDesk Coding Guidelines

## Comments and Docstrings
- Never write comments or docstrings referencing learning schedules, timelines, or phase markers (e.g., "Day 1", "Day 2", "Phase 1").
- Only add comments when strictly necessary to explain non-obvious function logic, invariants, or edge-case handling.
- Do not add comments stating what a line obviously does (no boilerplate restatements).
