The Complete 7-Stage End-to-End Query Lifecycle

Here is what happens when a query is transmitted from the user browser until the grounded response streams back or pauses for human review:

Stage 1: Public Customer Ingress & Network Isolation Port 8000 (app/api/v1/router.py)

HTTP POST request arrives at /v1/chat/completions. FastAPI inspects X-Thread-ID header. If missing, it generates a cryptographically random session UUID (session_xxxx). The compiled StateGraph is injected via Depends(get_graph). Both Port 8000 and Compliance Port 8001 run concurrently on a single asyncio event loop inside app/serve.py, sharing in-memory SSE event queues without Redis.

Stage 2: In-Graph Input Sanitization & Buffer Defense sanitize() (app/graph/nodes.py)

Raw string enters the state machine. re.sub(r'[\x00-\x1f\x7f-\x9f]', '', text) strips dangerous ASCII control characters and prompt-injection artifacts, collapses whitespace, and hard-caps input length to 2,000 characters to prevent buffer attacks or memory spikes.

Stage 3: Context-Aware Intent Classification classify_intent() (app/graph/nodes.py)

Multi-turn state check: If customer is in an active 2FA turn (auth_step == "awaiting_phone" or "awaiting_otp"), account lookup takes priority. Otherwise, regex scans for policy keywords (wire, fee, limit), dispute patterns (TXN-xxxx), or human requests. Intent is serialized to primitive string (Intent.POLICY_QUESTION.value) before returning to prevent JSON checkpoint serialization crashes.

Stage 4: Deterministic Conditional Edge Routing route_by_intent() (app/graph/router.py)

Reads state['intent'] against a strict 5-key mapping dictionary. All unrecognized, malformed, or hostile inputs fall back safely to out_of_scope_placeholder, guaranteeing zero unhandled exceptions.

Stage 5: Execution Subsystem Workflows RAG • HITL • 2FA • Escalation
  • Hierarchical RAG: Searches 160-char sentence child chunks using in-memory TF cosine vectorizer (zero PyTorch overhead). Retrieves parent 500-char paragraph chunks. Strict cosine threshold (>= 0.1500) grades relevance. Grounded generation synthesizes answer via pluggable multi-provider client (Ollama/OpenAI/Anthropic/Mock).
  • HITL Dispute: Parses transaction ID, generates DISP-xxxxxxxx case, freezes execution mid-node with LangGraph interrupt(). Compliance officer reviews on Port 8001 and resumes graph via Command(resume=...). State unfreezes and updates customer in real-time over SSE.
  • Core Banking 2FA: Multi-turn state machine generates 6-digit CSPRNG OTP (300s TTL). Evaluates 3-attempt brute-force lockout with SELECT ... FOR UPDATE row lock before any bypass logic. Queries balance and ledgers using raw parameterized PostgreSQL SQL.
  • Customer Care Escalation: Maps request to P1 Critical (< 3m), P2 High (< 10m), or P3 Standard (< 20m) SLA tiers. Persists ticket to PostgreSQL escalations table and displays in Port 8001 staff triage queue.
Stage 6: Disk-Backed Checkpoint Commit SqliteSaver WAL (app/graph/graph.py)

Replaced leaking MemorySaver with disk-backed SqliteSaver in WAL mode (checkpoints.db). Consumes ~2 MB RAM on disk, bounded heap footprint, and survives server restarts so paused disputes resume without loss.

Stage 7: Real-Time Response Delivery SSE Stream & JSON (Port 8000)

Streams response tokens chunk-by-chunk over standard HTTP/1.1 Server-Sent Events (text/event-stream). Delivers terminal data: [DONE] packet. Client UI renders markdown response instantly.

1. Outlaw MemorySaver

MemorySaver leaks heap RAM monotonically (no TTL eviction) and drops pending dispute frames on reboot. We mandate disk-backed SqliteSaver in WAL mode (~2 MB RAM).

2. String Intent Serialization

Python Enums raise TypeError when serialized to JSON blobs in checkpointers. Invariant: always return str(intent.value) before leaving nodes.

3. Lockout Precedes Bypass

The 3-attempt brute-force lockout check must execute strictly before master bypass validation. Otherwise locked accounts could be breached via replay attacks.

4. Docker POSIX shm_size: 128mb

PostgreSQL 16 shared_buffers=64MB crashes default Docker 64MB /dev/shm during parallel workers. Setting shm_size: 128mb prevents SIGBUS container crashes.

5. Row-Level Concurrency (FOR UPDATE)

Concurrent 2FA attempts and ledger transactions use SELECT ... FOR UPDATE inside explicit transaction blocks, serializing race conditions.

6. Single-Process Multi-Port Ingress

Ports 8000 and 8001 run on the same asyncio event loop via asyncio.gather. Enables Port 8001 to push directly to Port 8000 SSE queues without Redis.

7. Zero-Dependency TF Cosine Vector Store

Eliminates heavy PyTorch runtime (saves ~600 MB resident memory) by using pure Python TF vectorization with precompiled stopwords and numpy/math cosine similarity.

The 30-Second Elevator Pitch

"PolicyDesk is a high-assurance financial support platform built with LangGraph and FastAPI that guarantees deterministic workflow compliance. It isolates public customer interactions from internal operations across separate network ports, enforces Human-in-the-Loop approval for unauthorized transactions using graph interrupts, and implements hierarchical parent-child RAG to ground every answer without hallucination—all running within a strictly hardened 1 GB AWS Free Tier memory envelope."

The 2-Minute Architectural Pitch

"PolicyDesk was engineered around two hard constraints: regulatory financial compliance and micro-instance resource economics. In financial systems, agentic non-determinism is a liability. We designed a dual-port architecture where Port 8000 serves public customers and Port 8001 serves compliance officers. Both run in a single Python process under asyncio.gather, allowing compliance decisions on Port 8001 to push instant SSE updates to customer streams on Port 8000 without requiring an external Redis cluster.

Instead of naive single-pass RAG, we built a bounded Hybrid Corrective RAG (CRAG) pipeline: indexing 160-character child sentence chunks with Okapi BM25 + sqlite-vec dense embeddings (RRF fusion) while retrieving 500-character parent paragraphs with page/section citations, backed by a 0.1500 relevance gate, query rewriting, Stage-2 reranking, and post-generation grounding verification. For multi-turn transactions like disputes, the graph pauses mid-node using LangGraph's interrupt() and commits state to ThreadSafeSqliteSaver in WAL mode—avoiding the monotonic memory leaks of MemorySaver. All relational banking records live in PostgreSQL 16 tuned for 256MB RAM with row-level FOR UPDATE locking to eliminate 2FA race conditions, deployed cleanly on a $0 AWS Free Tier t3.micro instance."
